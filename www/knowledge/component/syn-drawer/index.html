syn-drawer

Current development status.
  • Stable: fully released and ready for production use.
  • Deprecated: use with caution as this component will be removed in the future.
  • Experimental: use with caution as it is in early access and potentially gets changes in the future.
stable 1.8.0

Description

Drawers slide in from a container to expose additional options and information.

Related components and links

  • Used in AppShell

Rules

Common use cases

  • Display supplementary information or options without navigating away from the main screen.
  • Provide contextual help or guidance related to the current screen.
  • House navigation menus on smaller devices.
  • Present filter options, forms or settings that users can interact with without losing their place.

Content

  • Ensure the content is supplementary and does not include critical information that users must see immediately such as notifications or alerts; instead, use syn-alert or syn-dialog for those purposes.
  • Check that the drawer content is fully visible and readable, even at larger font sizes.

Interaction and Behavior

  • Maintain the state of the content when it is reopened.
  • Avoid opening automatically without user interaction.
  • Provide multiple ways to close the interface for easy dismissal, such as a close button or clicking outside of it.

Layout

  • Ensure it does not cover critical content or actions on the main screen.
  • If using a tertiary action in the header, adjust the left padding to 0px for proper alignment.

Slots

  • Use the "header-actions" slot to add navigation and/or action elements if desired.
  • Use the "default" slot to add main content. The "default" slot is always scrollable.
  • Use the "footer" slot to add action elements if desired. The "footer" slot is always fixed.

Accessibility

  • Always provide a label for the drawer so that screenreaders correctly announce the component.
  • Make sure that the close button is always visible to ensure users are able to close the drawer.

Name Description
none (default) The drawer's main content.
label The drawer's label. Alternatively, you can use the `label` attribute.
header-actions Optional actions to add to the header. Works best with `<syn-icon-button>`.
footer The drawer's footer, usually one or more buttons representing various options.
Name Description Type Default Reflects?
contained By default, the drawer slides out of its containing block (usually the viewport). To make the drawer slide out of its parent element, set this attribute and add `position: relative` to the parent. boolean false Yes
label The drawer's label as displayed in the header. You should always include a relevant label even when using `no-header`, as it is required for proper accessibility. If you need to display HTML, use the `label` slot instead. string '' Yes
no-header Removes the header. This will also remove the default close button, so please ensure you provide an easy, accessible way for users to dismiss the drawer. boolean false Yes
open Indicates whether or not the drawer is open. You can toggle this attribute to show and hide the drawer, or you can use the `show()` and `hide()` methods and this attribute will reflect the drawer's open state. boolean false Yes
placement The direction from which the drawer will open. 'top' | 'end' | 'bottom' | 'start' 'end' Yes

Name Description Type
syn-after-hide Emitted after the drawer closes and all animations are complete. SynAfterHideEvent
syn-after-show Emitted after the drawer opens and all animations are complete. SynAfterShowEvent
syn-hide Emitted when the drawer closes. SynHideEvent
syn-initial-focus Emitted when the drawer opens and is ready to receive focus. Calling `event.preventDefault()` will prevent focusing and allow you to set it on a different element, such as an input. SynInitialFocusEvent
syn-request-close Emitted when the user attempts to close the drawer by clicking the close button, clicking the overlay, or pressing escape. syn-show Emitted when the drawer opens. SynShowEvent
